No persisted receipt/account record signature changes. Frontend adds AccountReport, AccountActivity, RewardLink, typed optional receipt footer observations and FooterDraft. ## Revision 1.7 — receipt RR correction and matching

Added transient ReceiptRRMatching.Option and Use records, typed frontend RRMatchUse and optional receipt paymentRoles/unidentifiedRR/accountName. Existing persisted receipt model signatures and SQL schema are unchanged. ReceiptCorrection.InvalidFields marks trusted correction-validation errors, distinct from opaque repository failures.


## Revision 1.8 — RR without an earning receipt

New transient ReceiptRRMatching.StandaloneMatch(RegisterReward reward, RRUsageLink link). Existing RegisterReward supports null earnedReceiptId, earnedDate and expirationDate; no persisted model signature changes. Frontend RewardLink.receiptId now explicitly accepts null.


## Revision 1.10 — independent Rewards inventory

Frontend StandaloneRR interface and ReceiptRRMatching.Option.historyUnknown are transient read contracts. Existing RegisterReward and RRUsageLink persisted signatures are unchanged. No account/receipt earning model is created by inventory registration.


## Revision 1.11 — visible recorded receipt calculations

New transient Java CalculationScenario and RecordedChecks records in TransactionCalculator; frontend CalculationScenario and optional Totals.calculationChecks. Persisted receipt/account types are unchanged.


## Revision 1.13 — reuse existing files and align CLI rebate display

Transient AccountActivityView nested types now belong to ProviderBalanceSummary; transient ReceiptRRMatching nested types belong to PostgresPlatformRepository. ReceiptCorrection and PrintedFooter remain package-private types in ReceiptInput.java. No persisted record signatures or JSON field shapes change. Source organization is consolidated without new files.
